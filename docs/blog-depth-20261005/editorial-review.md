# 2026-10-05 블로그 본문·FAQ 보강

사용자가 본문·FAQ의 답변 깊이가 부족하다고 지적하여 기존 글 3편을 같은 URL에서 확장했다. 승인 카드 15장과 검색 질문형 제목은 유지한다.

## 적용 내용

- 첫 문단은 40자 이내 직답을 유지하고, 본문에는 조건·판단 근거·설명 사례·확인 방법을 추가했다.
- FAQ는 글마다 3개, 각 답변은 독립적인 직답 뒤에 조건과 다음 행동을 설명한다.
- 수수료 환급: 대상/조회/실제 입금을 구분하고, 같은 상반기 개업 후 폐업한 가맹점의 확인 경로를 보강했다.
- 퇴직금: 세금 처리/근로자 판단/지급 요건을 구분하고, 구두 계약의 유효성과 서면 명시 의무를 분리했다.
- 부가세: 예정고지/예정신고 비교, 3분의 1 미달의 산술 예시, 확정신고 정산을 설명했다.
- 실제 상담 사례를 만들지 않았고, 설명용 계산을 개인별 세무 판단으로 제시하지 않았다.

## SEO·AI 답변 기준

Google의 공식 안내는 선호 글자 수나 AI 기능용 별도 특수 스키마가 없다고 설명한다. 분량 약 2,500~4,000자는 충분한 답변을 위한 편집 출발점이지 검색 노출 조건이 아니다. 핵심 답을 HTML 텍스트로 제공하고 공식 근거·대상·조건을 명확히 한다. FAQ 리치결과는 2026-05-07 종료 공지가 있으므로 기대 효과로 주장하지 않는다.

- https://developers.google.com/search/docs/fundamentals/creating-helpful-content
- https://developers.google.com/search/docs/appearance/ai-features
- https://developers.google.com/search/updates

실제 색인·순위·AI 인용 성과는 이번 작업에서 측정하지 않았다.

## 원고 검수 및 산출

지정 Claude 대화에서 새 확장 원고 3편 모두 PASS를 받았다. 요청과 실제 응답은 같은 폴더의 claude-request.txt, claude-response.txt에 저장했다. 선택 보완 2건(반복 단서 삭제, 소정근로시간 쉬운 풀이)을 반영했다. Claude 검수는 공식 사실 확인을 대체하지 않는다.

게시 산출물 생성에 필요한 build_blog.py 및 build_lastmod.py를 실행했다. 사용자 선호에 따라 자동 전체 코드 테스트·린트는 실행하지 않았다. 콘텐츠 검수와 실제 공개 확인은 별도로 수행한다.
