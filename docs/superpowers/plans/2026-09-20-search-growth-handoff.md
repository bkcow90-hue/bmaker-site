# bmaker.kr 검색 유입 확대 전략 및 Claude Code 작업 지시서

> For agentic workers: 실행 계획 스킬을 사용할 경우 superpowers:executing-plans로 작업 단위별로 진행한다. 별도 에이전트 생성은 이 문서의 필수 요건이 아니다.

**Goal:** 정책자금 기존 유입을 보존하면서 사업자대출 관련 자연검색을 확대해, 일 검색 노출 최소 3,000회와 네이버·구글 각각 일 검색 클릭 100회 이상을 목표로 한다. 핵심 검색어 TOP 3 진입, AEO/GEO 인용과 실제 유효 상담을 함께 개선한다.

**2026-09-20 목표 강화:** 11절의 목표 역산·순위 경쟁·AEO/GEO·외부 신뢰 확보 계획을 반드시 함께 실행한다. 첫 7개 페이지 개선은 첫 작업 묶음일 뿐 목표 달성이나 전체 프로젝트 종료를 의미하지 않는다. 성과를 보장하거나 목표를 낮추어 완료 처리하지 않는다.

**Architecture:** 기존 URL과 정적 HTML·생성 빌더 구조를 유지한다. 동일 검색 의도는 대표 페이지로 모으고, 제도 안내·기관 비교·사업 상황 안내의 역할을 구분한다. 검색량·실제 검색 실적·서비스 적합성을 결합해 순서를 정한다.

**Tech Stack:** 저장소의 정적 HTML/CSS/JS, Python 빌더, GA4, 기존 Python/브라우저 테스트. 호스팅의 실제 기준은 현재 wrangler.jsonc와 배포 워크플로다.

**Spec:** 본 문서 1~6절이 전략·범위 명세이고 7~10절이 실행·검증 계획이다. 사용자에게 이 문서를 전달하기 위해 작성했으며, 문서 생성 자체가 홈페이지 수정·배포 승인이나 SEO 성과 검증을 뜻하지 않는다.

## 2. 전략과 목표

### 핵심 방향

1. 자금명 유입 유지: 혁신성장촉진자금·재도전특별자금·청년고용연계자금·졸업후보 등 기존 검색 반응을 보존한다.
2. 기관명+대출 확대: 보증서대출·지역신용보증재단·신용보증기금·서울재단 관련 질문에 정확히 답한다.
3. 사업자 상황으로 확대: 개인사업자대출 조건, 신규 사업자, 기존 대출, 준비서류, 용도증빙, 비용 비교 등으로 넓힌다.
4. 실제 경험으로 차별화: 검증 가능한 익명 사례·자료 준비 예시·비교표를 사용한다. 공고를 바꿔 쓰는 데 그치지 않는다.

‘대출’ 단독 검색어, 직장인 급전·전세·주택담보·무직자대출까지 무차별 확장하지 않는다. 사업자가 검색하는 넓은 대출 질문에는 답하되, 회사가 직접 돈을 빌려주거나 모든 금융상품을 취급한다고 오인시키지 않는다.

### 목표 정의

- 필수 목표: 일 검색 노출 최소 3,000회 + 네이버 자연검색 일 클릭 100회 이상 + 구글 자연검색 일 클릭 100회 이상. 노출 3,000회는 우선 합산 하한으로 해석하며, 플랫폼별 3,000회인지 사용자 정의가 확인되면 기록을 갱신한다. 해석을 숨기지 않는다.
- 실무상 노출 목표는 클릭 100회를 플랫폼마다 확보하는 데 필요한 값으로 역산한다. 합산 노출 3,000회를 채웠어도 플랫폼별 클릭 목표가 미달이면 목표 미달이다. 90일은 실행·평가 주기이지 달성 보장 시한이 아니다.
- 실제 성과 판단: 자연검색 클릭, 비브랜드 유입, 실제 수신된 상담, 서비스 대상에 맞는 상담 수.
- 일 페이지뷰 2,300회는 별도 장기 목표다. 검색 노출 3,000회와 같은 규모로 취급하지 않는다.
- 계산 예시: 일 노출 3,000회 × CTR 3~5% = 90~150 검색 클릭. CTR 3~5%는 가정이며 예측값·업계 평균이 아니다.
- 노출·검색 클릭·세션·사용자·페이지뷰·상담을 구분한다. 서로 다른 검색엔진의 평균 순위를 합치지 않는다.
- 최근 28일 고정 비교와 최신 완료 7일 추세를 함께 본다. 공고 개시·마감 등 계절성, 네이버 집계 지연, 검색엔진별 날짜 기준 차이를 기록한다.

## 4. 반드시 보존할 내용과 운영 규칙

- 먼저 AGENTS.md, CLAUDE.md, docs/homepage-standard.md, .agents/product-marketing.md를 전부 읽는다. 과거 대화의 호스팅 설명·숫자보다 현재 설정과 승인된 규격을 우선한다.
- git status 확인 후 git pull --ff-only. 작업 충돌이 있으면 변경을 보존하고 충돌 지점만 보고한다. git reset --hard, git checkout -- ., 사용자 변경 삭제 금지.
- 사업자대출 개선을 이유로 홈페이지를 금융 단일 서비스 사이트로 바꾸지 않는다. 광고·창업·인증 서비스와 service_category를 보존한다.
- 가이드북 제공 이벤트 유지. 정책자금 뉴스의 제목·기사 제목을 이 작업에서 바꾸지 않는다. 뉴스에 인스타그램을 다시 추가하지 않는다.
- 현재 디자인과 첫 화면 구성 유지. 과거 캡처를 근거로 히어로·서체·색상·사진을 되돌리지 않는다.
- 기존 URL·소유권 인증 메타태그·개인정보 동의·상담 폼·전화/카카오 경로·기존 GA4를 보존한다.
- ‘대표가 전 과정 관리 / 담당자가 바뀌지 않습니다’가 남아 있다면 실제 운영과 맞지 않는 확약을 제거한다. 사용자가 대표도 관여하고 상담 전담 직원도 있다고 설명했다. 대체 문구: ‘상담팀과 대표의 협업 / 전담 상담 직원이 상담을 진행하고, 대표가 함께 관여합니다.’ 업무 범위나 검토 빈도를 추가로 보장하지 않는다.
- 회사는 민간 회사이며 정부기관·은행이 아니다. 승인·금리·한도·기간 보장, 실재하지 않는 제휴·자격·후기·실적 생성 금지.
- 성공보수 요율·계산 방법 비공개 유지. 기존 서비스별 비용 정책을 다른 서비스로 확대하지 않는다.
- 원장 구글시트·CSV·xlsx의 사례 숫자를 손으로 변경하지 않는다. 실제 실적은 기존 데이터 생성 경로를 사용한다. 집계 기간·분모·정의가 다른 수치를 억지로 통일하지 않는다.
- 상담→정산 기간을 신청→입금 기간으로 바꾸지 않는다. 평균과 중앙값의 계산 의미를 문구 편의를 위해 바꾸지 않는다.
- 은행상품 취급·대출 중개 가능 여부·법적 자격은 확인되지 않은 상태에서 새로 주장하지 않는다. 필요한 확인은 해당 주장만 보류하고 다른 작업은 계속한다.

## 5. 이번 지시서 실행 시 먼저 반영할 규격 수정안

사용자가 이 문서를 실행 지시로 전달한 경우 다음 SEO 원칙 변경을 작업 범위로 삼는다. docs/homepage-standard.md에 변경 이유와 실제 작업일을 먼저 기록한다. 다른 사업·디자인 규칙을 임의로 바꾸지 않는다.

1. 기존 ‘검색어 1개 = 전용 페이지 1개’를 ‘검색 의도 묶음마다 대표 페이지를 둔다. 띄어쓰기·유사어·연도 변형은 함께 설명하고, 답변·자료·독자 상황이 실질적으로 다를 때만 별도 URL을 만든다’로 변경한다.
2. ‘100~1,000건대 저경쟁이 핵심 / 10건 미만 제외’를 절대 기준으로 사용하지 않는다. 광고 경쟁도는 SEO 난이도가 아니며, 검색량은 서비스 적합성·실제 검색 실적·내용 차별성과 함께 판단한다. 검색량 미표시라도 기존 고객에게 필요한 질문은 다룰 수 있다.
3. ‘검색 문장 그대로 FAQ’를 맥락이 명확한 실제 고객 질문으로 다듬을 수 있게 한다. 오타·특수기호·불완전 문장을 제목에 복제하지 않는다.
4. title·description 길이는 편집 가이드이지 순위 보장 공식이 아니다. 핵심 의도·가독성·정확성을 우선하고 키워드를 나열하지 않는다.
5. 날짜는 실질적인 내용 변경과 확인 근거를 반영한다. 단순 빌드만으로 모든 페이지를 최신 정보처럼 표시하지 않는다. 기존 build_lastmod 동작과 충돌 여부를 검사한다.
6. 공식 제도 조건과 회사 사례 통계를 구분한다. 공식 조건 숫자가 필요한 설명에는 현재 공식 공고·기준일·적용 범위를 붙인다. 회사가 제공하는 확정 조건처럼 쓰지 않는다. 실적 숫자는 기존 원장/빌더 규칙을 유지한다.

robots/AI 크롤러/llms는 11절에 따라 접근·일관성을 점검하고 필요한 저장소 내 최소 수정을 검증한다. Cloudflare 계정 정책·WAF 변경은 구체적 대상과 영향 확인 후 별도 승인으로 처리한다. AI 학습 허용과 검색 노출 허용을 동일하게 취급하지 않는다. 파일·스키마 추가로 순위나 AI 인용이 보장된다고 쓰지 않는다.

### 페이지별 공통 구성

첫 설명은 검색자가 묻는 질문에 바로 답한다. 이후 적용 대상·예외, 비교 또는 준비 목록, 신청 흐름, 관련 사례, FAQ, 공식 출처와 기준일, 실제 작성/검토자, 다음 행동을 배치한다. 모든 페이지에 똑같은 항목을 억지로 넣지 말고 의도에 맞게 구성한다.

- 최신 조건·접수 여부는 중소벤처기업부, 소상공인시장진흥공단, 중진공, 신용보증기금, 기술보증기금, 해당 지역 재단·지자체의 공식 자료로 확인한다.
- 실시간 접수 가능 여부를 날짜 계산만으로 확정하지 않는다. 조기 마감·예산 소진 가능성과 공식 확인 경로를 구분한다.
- 본문을 키워드 설명으로 길게 늘리지 않는다. 표·실무 예시·체크리스트는 실제 결정을 돕는 경우에만 추가한다.
- 임의의 승인확률·최대한도 계산기나 확정 자격 판정 기능은 만들지 않는다.
- CTA는 기존 무료 진단 경로와 디자인을 재사용한다. 정보를 읽기도 전에 상담을 강요하지 않는다.

2. title/H1의 전후 및 핵심 내용 변화.
3. 변경한 원본·빌더·HTML 파일.
4. 공식 출처, 확인일, 미확인 사실.
5. 테스트 결과와 모바일/데스크톱 미리보기.
6. 측정이 준비된 항목과 실제 계정/메일에서 미검증인 항목.
7. 2차 후보와 보류 이유.
8. 배포 여부: 기본은 미배포. 사용자 배포 승인 후에만 push하고 라이브 응답·내용·동작을 재검증한다.

테스트 통과는 검색 순위 상승을 입증하지 않는다. ‘SEO 작업 완료’와 ‘검색 성과 달성’을 별도로 보고한다.

## 9. 2차 콘텐츠 및 90일 운영 계획

1차 검증을 마치면 결과를 보고하고 11절의 성과 계획에 따라 2차 로컬 초안·구현을 이어간다. 최초 신규 콘텐츠는 최대 4개를 하나의 검증 묶음으로 삼고, 기존 페이지와 겹치면 기존 문서 보강으로 대체한다. 4개는 전체 콘텐츠 수의 상한이 아니다. 배포·외부 게시 권한은 1절을 따른다.

후보:

- 신규 개인사업자의 대출 준비: 업력·매출 자료·용도와 경로 비교.
- 기존 대출이 있는 사업자의 준비: 잔액·월 상환액·만기·보증 이용 현황 정리. 가능 여부 확답 금지.
- 사업자대출 비용 비교: 금리·보증료·상환 방식·중도상환 조건의 구분. 특정 상품의 현재 숫자는 공식 확인 후만 사용.
- 사업자대출 준비서류·용도증빙: 실제 정리 예시. 허위 작성·목적 외 사용 유도 금지.

최종 URL은 현재 /situation 등 프로젝트 관례와 기존 주제 중복을 확인한 후 결정한다. 위 후보를 검색어마다 여러 페이지로 복제하지 않는다.

운영안:

- 1~2주: 기준선·소스 매핑과 1차 7개 페이지 작업/검증.
- 3~4주: 승인된 2차 콘텐츠 최대 4개와 네이버 블로그용 원고 주 1개. 블로그에서도 질문에 충분히 답하고 추가 비교표·자료를 홈페이지로 연결한다. 자동 외부 게시 금지.
- 5~8주: 성과가 있거나 고객 효용이 검증된 주제 중심으로 주 1개 신규/주 1~2개 업데이트. 실무 검토 역량에 맞춰 발행량을 줄일 수 있다.
- 9~12주: 성과 없는 페이지의 색인·수요·의도·중복을 점검하고 개선한다. 단지 단기 클릭이 없다는 이유로 삭제하지 않는다.

평가 규칙:

- 색인 문제면 수집·응답·canonical·내부 링크를 먼저 확인한다.
- 색인은 됐지만 노출이 없으면 수요·주제·내용·최근 게시 시점을 확인한다.
- 노출 증가/클릭 정체면 검색어별 순위·기기·검색 의도·제목을 확인한다. 사이트 전체 CTR 하나로 결정하지 않는다.
- 클릭 증가/유효 상담 정체면 대상 고객·콘텐츠 기대·CTA·실제 문의 수신을 확인한다.
- 브랜드, 자금명, 기관+대출, 사업자 상황, 기타 서비스로 나눠 추적한다. 구글은 익명 검색어의 분류 불가 부분을 남긴다.
- +14일은 구현·색인·초기 신호 확인, +28일은 같은 기준의 실적 비교, +56/84일은 확장 판단으로 사용한다. 14일 안에 성과가 없다고 SEO 실패로 단정하지 않는다.
- 정기 측정은 운영 계획일 뿐이다. 별도의 자동화/예약 작업은 사용자가 요청할 때만 만든다.

## 11. 목표 강화: 상위 순위·AEO/GEO·유입 규모를 함께 달성하는 실행안

### 11-1. 결과 지표와 목표 역산

고정 결과 목표는 플랫폼별 자연검색 클릭 100회/일 이상이다. 당일 급증 한 번으로 ‘달성’ 처리하지 않는다. 완료된 최근 28일 평균에서 각 플랫폼 100회/일 이상을 기본 지속 성과 기준으로 삼고, 각 일자 목표 미달 일수도 함께 보고한다. 사용자의 ‘최소 매일’ 요구는 평균만으로 충족했다고 주장하지 않는다. 네이버는 확보 가능한 확정 일자 범위와 보고 지연을 명시한다.

| 플랫폼별 가정 CTR | 각 플랫폼 100클릭/일에 필요한 노출 |
|---|---:|
| 2.1% | 약 4,762/일 |
| 3% | 약 3,334/일 |
| 5% | 2,000/일 |
| 8% | 1,250/일 |

이 표는 산술 시나리오이며 순위별 CTR 보장치가 아니다. 현재 구글 CTR 2.1%가 유지되면 구글만 약 4,762노출/일이 필요하다. 양쪽 5%라면 합산 약 4,000노출/일이 필요하다. ‘노출 최소 3,000’은 상한이 아니므로 클릭 달성에 필요한 노출을 더 확보한다.

초기 합산 노출 6,000~10,000/일 범위도 필요한지 수요 모델로 검토한다. 달성 가능한 시장 규모라고 단정하지 않는다. ‘하루 100클릭’은 월 30일 단순 환산 시 플랫폼별 약 3,000클릭이고 구글 현재 28일 92클릭에서 2,800클릭으로 약 30.4배 확대하는 과제다.

docs/seo-demand-model-2026-09-20.csv를 만든다. 열은 platform, intent_cluster, representative_url, observed_clicks, observed_impressions, observed_period, market_volume_source, market_volume_period, eligible_searches_assumption, visibility_assumption, ctr_assumption, estimated_clicks_low, estimated_clicks_high, confidence_reason, next_action이다. 원자료가 없는 칸은 미확인으로 두고 구글 수요를 네이버 수치로 대체하지 않는다. 관련 키워드·URL 간 중복 기회를 보수적으로 처리한다. 예상 클릭 합계가 목표를 뒷받침하지 못하면 주제 확대·콘텐츠·유통·기간·자원 중 무엇이 얼마나 더 필요한지 밝힌다.

유효 상담과 매출 연결도 별도로 본다. 필요한 상담 수 = 필요한 계약 수 / 관측 계약 전환율, 필요한 클릭 수 = 필요한 유효 상담 수 / 관측 유효 상담 전환율이다. 실제 전환율·기여이익이 없으면 경제성이 입증됐다고 쓰지 않는다. 200클릭/일 달성만으로 사업 생존이 보장되지 않는다.

### 11-2. TOP 3 경쟁 작업을 별도 과제로 수행

- [ ] 고정 핵심 비브랜드 검색 의도 20개를 선정한다. 브랜드·띄어쓰기 변형으로 개수를 채우지 않고 수요와 실제 고객 적합성 근거를 붙인다.
- [ ] 네이버·구글 각각 현재 결과를 표본 확인한다. 날짜·지역·기기·검색어·자사 URL·관찰 순위·상위 3개 결과 URL·광고/블로그/지도/AI 블록 유무를 기록한다. 자동 무단 검색 스크래핑을 만들지 않는다. GSC/API/허용된 도구·사람의 제한적 확인을 사용한다.
- [ ] 네이버의 웹문서 내 순위, 블로그 블록 순위, 화면 전체 위치를 섞지 않는다. 웹문서 1위라도 광고·다른 블록 아래이면 첫 화면 가시성은 낮다고 별도 기록한다.
- [ ] 상위 문서 대비 빠진 답변, 실무 예시, 공식 근거, 업데이트 상태, 기관 탐색 의도, 비교 기능, 모바일 읽기 경험, 저자/회사 신뢰를 항목별 비교한다. 경쟁사 내용을 복사하지 않는다.
- [ ] docs/seo-serp-gap-2026-09-20.csv에 검색어별 가장 큰 격차 1~3개, 구체적 수정, 근거 URL, 담당 페이지, 확인 방법을 기록한다. ‘키워드 더 넣기’만으로 분석을 끝내지 않는다.
- [ ] 같은 의도를 여러 자사 페이지가 나눠 받는지 실제 검색어→페이지 자료를 확인한다. 문제가 입증되면 대표 페이지 선택·내부 연결·중복 설명 정리를 제안한다. 단순 여러 URL 등장만으로 강제 합치지 않는다.
- [ ] 순위 4~10위이며 검색 의도와 서비스가 맞는 페이지는 우선 개선 후보, 11~20위는 내용·관련성 격차, 20위 밖/미노출은 수요·색인·주제 적합성부터 확인한다. 숫자는 운영 분류이지 알고리즘 공식이 아니다.

산출물 지표: 고정 20개 의도의 플랫폼별 관찰 TOP 3 비율, TOP 10 비율, 웹문서가 첫 화면에 있는 비율, 쿼리별 GSC 평균 순위, 실제 클릭. TOP 3가 아닌 결과도 클릭이 생기므로 ‘3위 밖은 가치 0’으로 처리하지 않는다. 초기 도전 지표는 20개 중 10개 TOP 3이며, 현재 순위·경쟁 데이터 확인 후 난이도·실행기간과 함께 명시한다. 달성 가능성을 확인하지 않고 약속하지 않는다. 쉬운 무수요 검색어로 목표를 대체하지 않는다.

모바일 속도는 먼저 측정한다. GSC 실제 사용자 지표와 실험실 측정을 구분하고, 주요 콘텐츠 표시·레이아웃 이동·상호작용을 방해하는 확인된 원인을 수정한다. 측정 없이 새 프레임워크·전면 CSS 개편을 도입하거나 속도만으로 TOP 3를 보장하지 않는다.

### 11-3. AEO/GEO를 접근·답변·근거·유통·측정으로 구현

- [ ] Googlebot·Yeti 등 검색 크롤러와 OAI-SearchBot 등 AI 검색용 크롤러의 접근 정책을 공식 문서로 확인한다. 실제 robots.txt·meta/header 미리보기 제한·응답코드·가능한 CDN 로그를 검사한다. User-Agent 문자열만 바꾼 200응답을 실제 크롤러 접근 보장으로 해석하지 않는다.
- [ ] AI 학습용 GPTBot/Google-Extended 허용을 AI 검색 상위 노출의 필수조건으로 삼지 않는다. Cloudflare 전체 보안 기능을 끄지 않고, 확인된 차단 원인과 필요한 최소 변경만 제안한다.
- [ ] 핵심 질문별로 완결된 직접 답변, 조건/예외, 공식 출처, 실제 확인일, 저자·검토 주체를 본문에 둔다. 기관·상품·보증료·기간 정의가 앞뒤에서 달라지지 않아야 한다.
- [ ] 비교표와 실제 사례 요약은 HTML 본문으로 제공한다. 다운로드 폼이나 이미지 안에만 중요한 답을 가두지 않는다. 실제 FAQ와 구조화 데이터의 내용 일치를 검증한다.
- [ ] llms.txt와 llms-full.txt는 기존 사실·링크의 일관성을 유지하는 보조 자료로 관리한다. 새 ‘AI 전용 키워드 문서’를 양산하지 않는다. 구글 AI 노출에 특별한 스키마나 AI 텍스트 파일이 필수라고 주장하지 않는다.
- [ ] 사례는 기간·대상·분모·산정 기준·동의/익명화 범위를 명시한다. 같은 사례 ID가 페이지마다 다른 기관·금액으로 설명되거나 요약 통계가 원장과 다르면 공개 원본을 바꾸지 말고 근거를 대조해 수정 또는 보류한다.
- [ ] 회사·대표·연락처·주소·실제 자격·서비스 범위를 사이트와 확인 가능한 외부 프로필에서 비교한다. 외부 계정 변경은 승인 범위에 따르고 허위 권위·독립 후기·인용을 만들지 않는다.

AI 평가 질문은 docs/measure-log.md의 기존 고정 질문을 보존하고, 사업자대출 질문 12개를 더해 고정 20개 묶음으로 만든다. 각 질문별로 검색 사용 여부, 플랫폼/모델, 날짜, 질문 원문, 새 대화 여부, 회사 언급, bmaker.kr 직접 링크 인용, 사실 오류, 실제 유입을 구분해 기록한다. 개인화·응답 변동 가능성을 명시한다. 유리한 답이 나올 때까지 재시도한 결과만 보고하지 않는다. 관찰 패널의 인용률은 전체 시장 AI 노출수나 검색 점유율이 아니다.

GSC 화면의 생성형 AI 실적 보고서가 실제 제공되면 확인한다. 별도 AI 보고서의 지표가 기존 웹 검색 총계에 포함되는지 현재 문서와 UI로 확인해 중복 합산하지 않는다. 보고서 미제공은 0노출이 아니라 미확인이다. ChatGPT/Perplexity 등은 실제 referrer·허용된 UTM으로 유입을 분리하되 미식별 유입을 추정으로 채우지 않는다. AI 답변에 언급됐다고 홈페이지 클릭이 생긴 것으로 계산하지 않는다.

### 11-4. 사이트 밖의 신뢰와 유통도 작업 범위에 포함

사이트 내부 수정만으로 경쟁 격차가 줄지 않으면 아래를 함께 추진한다. 코드 에이전트가 수행할 수 있는 조사·초안·페이지 제작과, 대표/직원이 수행해야 하는 자료 확인·게시·협업을 분리한다.

- 첫 30일에 검증 가능한 자료형 콘텐츠 2개를 준비한다. 예: 익명 사례 기반 자금 준비 과정 분석, 경로별 준비서류/용도증빙 체크리스트. 기간·표본·한계와 공식 출처가 있어야 한다. 원자료 없이 ‘독자 조사’ 통계를 만들지 않는다.
- 실제 자료와 동의가 있는 상세 사례 4개를 우선 검토한다. 임의 선정 효과·불리한 결과 누락을 승인율 통계로 포장하지 않는다.
- 네이버 블로그는 주 1~2개 실무 검토 가능한 원고를 준비한다. 블로그 자체에서 유용하게 답하고 홈페이지의 더 상세한 원자료·도구·비교표로 연결한다. 복제·낚시·게시 수 채우기 금지.
- 관련 업종 단체·창업 커뮤니티·세무/노무 등 실제 협업 가능 주체 10곳을 공개 자료로 조사하고, 상위 3곳에 대한 구체적인 자료 제공/교육 제안 초안을 준비한다. 외부 전송·가입·게시·협약은 사용자 승인 후 수행한다. 순위용 링크 구매·링크 교환망은 제외한다.
- 기존 실재하는 업체 프로필의 상호·주소·서비스·연락처를 정리한다. 가짜 지점이나 지역 페이지만 늘려 지도 노출을 만들지 않는다.

유통 성과는 게시 수·백링크 수 자체가 아니라 적합한 독자 유입·자료 참조·상담을 본다. 위 수량은 첫 작업 묶음이며, 원자료와 인력 여력에 따라 보고 후 조정한다.

### 11-5. 운영과 자원 재배분

- 개발/분석 담당: 소스·색인·중복·측정·페이지 구현·검증. 검색어 자료를 추가로 받지 못해도 확인 가능한 기술/콘텐츠 작업을 계속한다.
- 대표/실무 검토 담당: 금융 조건과 서비스 범위 확인, 사례·공식 출처 대조, 상담에서 반복되는 질문 수집.
- 콘텐츠/배포 담당: 홈페이지 초안·블로그 원고·승인된 게시·협업 연락. 담당자가 없으면 필요한 주당 시간을 추산해 대표에게 제시하고 작업량을 조정한다.
- 매주 바뀐 사실, 실시한 변경, 결과, 다음 투자할 주제, 중단/보류할 주제를 보고한다. 글 수나 테스트 통과를 목표 클릭 달성으로 치환하지 않는다.
- +28일에 기술적 접근은 정상인데 비브랜드 노출/클릭이 늘지 않으면 반복 발행을 멈추고 검색 의도·상위 문서 격차·외부 근거를 재평가한다. +56일에도 정체면 시장 수요·콘텐츠 우위·신뢰 확보·필요 자원의 가정을 수정한다. 신생 문서의 짧은 관측만으로 삭제하지 않는다.
- 90일 후에도 목표가 미달이면 미달을 명시하고 남은 격차·다음 실험·비용을 제시한다. ‘할 수 있는 작업을 다 했다’는 이유로 목표 달성 처리하지 않는다.
- 생존에 필요한 단기 문의는 SEO와 별도 관리한다. 사용자와 예산·목표 상담단가·손익 기준을 확인한 후에만 유료 검색/기존 고객 소개/제휴 같은 보완 채널을 실행한다. 유료 클릭을 자연검색 100클릭 목표에 합산하지 않는다.
- 포괄적인 ‘무엇이든’ 요청을 허위 리뷰·스팸·검색 순위 조작·개인정보 노출·무단 비용 지출의 허가로 해석하지 않는다. 단기 숫자를 위해 검색/사업 신뢰를 손상시키지 않는다.
