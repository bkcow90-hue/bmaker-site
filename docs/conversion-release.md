# 상담 전환 개선 — 2026-09-07

목적: 첫 화면에서 정책자금 상담의 목적과 신청 경로를 명확히 하고, 전송 실패를 예약 성공으로 표시하는 문제를 해결한다.

## 반영 내용
- 홈페이지의 추상적인 제목을 정책자금·사업자대출 상담 목적에 맞게 수정. 기존 브랜드 색상 유지.
- 단일 상담 폼을 첫 화면에 배치. 성함·연락처·개인정보 동의 필수, 업종·시간대·문의 내용은 선택 펼침.
- 초기 신청에 서류 첨부가 필요 없음을 안내. 대표 소개와 공개 증빙 경로는 폼 다음에 유지.
- 모바일 하단 상담/카톡 경로. 폼이 보이거나 입력 중일 때 하단 바를 숨김.
- 접수 API의 `ok: true`와 `delivery: accepted`를 함께 확인한 뒤에만 성공 처리. accepted는 메일 서비스 접수이며 수신함 도착 보장은 아님.
- 22초 전송 제한, 재시도 중복 키, 중복 클릭 차단, 오류 시 입력 유지·대체 연락 경로.
- 모든 안내 페이지에 간편 상담 링크 및 동일한 이벤트 스크립트 적용. 생성 스크립트에도 반영.
- 실행 건수 제목의 고정값 제거, 사례 ID와 날짜 구분, 금액 문자열 잘림 제거, 기관 설명 보완.
- 자동 계산일과 자료 확인일 구분. 상시형/예산소진형을 날짜만으로 접수 중이라고 판정하지 않음.
- 상담 통계는 916개 고유 업체로 단정하지 않고 신청 기록 916건으로 표시. 별도 모수의 비율을 합산한 해석 삭제.

## 배포 순서
codedaum/functions/api/lead.js 수정본을 먼저 배포한 뒤 bmaker-site를 배포한다.
기존 자가진단 클라이언트는 delivery_required를 보내지 않으므로 기존 동작을 유지한다.
홈페이지는 delivery_required=true를 보내므로 메일 서비스 오류·키 누락 시 실패로 표시한다.
실제 메일 전달 경로는 운영 발송 로그에서 추가 확인해야 한다. 테스트 중 실제 메시지는 전송하지 않았다.

## 측정 연결 상태와 지표
원본 저장소에 GA4/GTM 식별자가 없다. 임의의 ID를 넣거나 별도 분석 계정을 만들지 않았다.
conversion.js는 gtag가 있으면 해당 계정으로 이벤트를 보내며, 없으면 dataLayer에 큐잉한다.
GA4 스니펫 또는 GTM 컨테이너의 연결 및 이벤트 태그 설정 전에는 보고서에 수집되지 않는다.

| 이벤트 | 의미 |
|---|---|
| consultation_click | 상담 신청 경로 클릭 |
| consultation_start | 최초 입력 |
| consultation_validation_error | 필수값 검증 실패 |
| consultation_submit | 유효한 폼 전송 시도 |
| consultation_error | 전송/응답 확인 실패 (원인 코드만) |
| generate_lead | 메일 서비스가 접수한 상담 신청 |
| kakao_click | 카톡 링크 클릭 (상담 완료와 다름) |
| phone_click | 전화 링크 클릭 (실제 연결과 다름) |

분석 이벤트에는 이름·전화번호·문의 내용·URL 쿼리를 넣지 않는다. 기존 분석 설정에서 URL 쿼리를 수집하는지도 별도 확인 필요.
실제 신청 전환율 = 접수 성공 세션 / 대상 랜딩 방문 세션. 유입 경로·모바일/PC별로 비교한다.
상담 연결률과 유효 상담률, 계약 전환은 별도 운영 지표로 확인한다. 현재 기준선과 개선율은 측정하지 않았으며 상승률을 주장하지 않는다.

## 검증
기존 Python 회귀 테스트, 추가 상담 흐름/집계/접수 상태 테스트, 모의 fetch 기반 JavaScript 테스트.
API는 성공·발송 실패·키 누락·재시도·중복키·잘못된 입력·CORS·기존 클라이언트 호환성을 검증한다.
로컬 클라우드 브라우저 접속 제한으로 모바일 시각 검증은 완료하지 못했다.
