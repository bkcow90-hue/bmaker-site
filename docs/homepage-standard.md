# 비즈니스 메이커 홈페이지 제작 규격 (bmaker.kr)

기준일: 2026-09-19 · 적용 범위: bmaker.kr 전 페이지, 광고 랜딩, 빌더·템플릿·CSS·JS
읽는 사람: Claude Code, Codex, 그 외 이 저장소를 편집하는 모든 에이전트

이 문서는 사이트 작업의 단일 기준이다. 페이지·카피·CSS·빌더를 만지기 전에 읽는다.
작업이 규격과 충돌하면 코드가 아니라 이 문서를 먼저 고치고(변경 이력 남김), 그 다음 코드를 고친다.
규격에 없는 판단은 대표에게 묻는다. 추측으로 채우지 않는다.

---

## 0. 원칙

- 문의 = 유입 × 전환율. 홈페이지는 "문의를 받을 준비가 된 그릇"이다. 유입은 별도로 부어야 한다.
- 브랜드 톤: 빈말하지 않는다. 다 되는 것처럼 말하지 않는다.
  마무리 문장: "다 되는 것처럼 말씀드리지 않습니다. 대신, 될 수 있는 방법을 함께 찾겠습니다."
- 회사명 표기는 "비즈니스 메이커"(띄어쓰기) 하나로 통일한다. 로고 이미지 외에 "비즈니스메이커", "BUSINESS MAKER"를 본문·title·JSON-LD에 쓰지 않는다. (JSON-LD alternateName은 검색엔진용 별칭이라 예외 — 비즈니스메이커·Business Maker 유지)
- "진단"은 서비스명, "정책자금 컨설팅"은 카테고리다. 둘 다 있어야 한다. 컨설팅이라는 단어를 진단으로 바꿔 없애지 않는다(AI·검색이 업종을 잃는다).
- 검색 얼굴(홈 title·description·히어로)은 정책자금 단일, 다른 업무는 사이트 안에서만.
- 섹션당 메시지 하나. 한 섹션에 두 가지 말을 넣지 않는다.
- 사장님이 바로 알아듣는 말로 쓴다. 업계·통계 용어, 자체 조어, AI스러운 말투 금지.

## 1. 콘텐츠 금지·치환 (전 페이지)

| 금지 | 대신 |
|---|---|
| "100% 승인", "무조건", "보장" 등 보장성 문구 | 쓰지 않는다. 승인은 기관 심사 권한임을 명시 |
| "갚다" 계열(갚아야·갚는·갚아도) | "상환", "돌려주다" |
| "실행 기록", "중앙값", "실행 건수" | "받은 사례", "건당 평균", "보통 N일" |
| 사례에 "전건 공개", "전부 공개" | "익명 일부 공개 · 기간", "받은 사례 보기" |
| 기관 공고 최대치를 자기 조건처럼("최대 10억", "연 2%부터") | 원장 집계값만("실행 사례 기준 금액 min~max · 금리 연 min~max") |
| "신용점수 부족해도", "저신용 OK" 류 | 쓰지 않는다 |
| 손으로 쓴 실적·조건 숫자 | build_cases가 원장에서 생성한 값만 |
| "전국 비대면 상담" | "전국 무료 상담(대면·비대면 선택)" |
| 히어로·CTA 근처의 성공보수·비용 언급 | "진단은 무료, 정책자금은 착수금이 없습니다" 한 줄만. 나머지는 FAQ |

- 면책 조항과 작성자 서명은 모든 안내 페이지에 둔다.
- bmaker.kr과 codedaum 두 사이트의 실적 숫자는 항상 같아야 한다.
- 원장 익명화 범위는 사례 주석에 그대로 명시: 지역·업종·매출 구간은 범주화·일부 조정, 기관·자금·금액·금리·실행 시점은 실제.

## 2. SEO

- 검색어 1개 = 전용 페이지 1개. 한 페이지가 여러 검색어를 담당하지 않는다.
- 페이지마다: 고유 title(핵심검색어 | 보조검색어 | 비즈니스 메이커, 50자 내외), description 150자 내외, canonical, h1 1개.
- 정본 URL은 확장자 없는 형태(/sojingong). canonical·sitemap·llms.txt·내부링크 전부 이 형태. 새 페이지도 동일.
- 기관·제도명은 정식명칭(약어) 병기: 소상공인시장진흥공단(소진공).
- 각 페이지에 "본 안내는 YYYY년 M월 기준". 푸터 "최종 업데이트"와 JSON-LD dateModified, sitemap lastmod는 build_lastmod가 자동 삽입 — 손으로 쓰지 않는다.
- 홈 head의 Google Search Console 소유권 메타태그는 영구 유지. 삭제 금지.
- www → 루트 301(Cloudflare 리다이렉트 규칙, Preserve query string 켬). Netlify식 `/* / 301` 캐치올은 무한 리다이렉트 — 사용 금지.
- 검색 등록 3곳(네이버 서치어드바이저·Google Search Console·Bing Webmaster)은 도메인 기준이라 유지된다. MX 등 메일 레코드는 절대 건드리지 않는다.
- 홈 title·H1·라벨은 전국 기준, 지역어 금지. 지역 검색은 지역 랜딩(/gangseo 등)과 프로필·JSON-LD 주소가 담당한다.

## 3. GEO

- robots.txt: GPTBot·OAI-SearchBot·ClaudeBot·PerplexityBot·Google-Extended·Yeti 명시 허용. Cloudflare의 AI 학습 차단 옵션은 끈다.
- llms.txt·llms-full.txt 필수. 회사 요약, 주요 페이지, 회사의 관점(착수금 0원·거절은 진단서·선별 진행), 핵심 사실(면책 포함). 사이트 수치·전화번호와 항상 일치. 응답 헤더 `text/plain; charset=utf-8`(_headers).
- FAQ: 질문은 실제 검색 문장 그대로, 답변 첫 문장이 완결된 직답. 화면 FAQ와 FAQPage JSON-LD는 100% 일치 — FAQ를 고치면 스키마도 같이 고친다.
- 구조화 데이터 세트: FAQPage·Service·BreadcrumbList·WebSite·ProfessionalService(LocalBusiness, telephone·sameAs 포함). 비벗(NHN KCP)은 sameAs가 아니라 memberOf.
- sameAs에는 실제 등록된 프로필만(인스타·구글 비즈니스 프로필·네이버 스마트플레이스·당근·카카오맵). 등록 안 된 채널을 미리 넣지 않는다.
- 상세 페이지 간 "함께 보면 좋은 안내" 상호 링크로 주제 클러스터.
- 회사명·대표·전화·주소는 전 채널 동일 표기(상호 "비즈니스 메이커", 마곡 공항대로 213, 1666-2425).

## 4. 전환

- 첫 화면 CTA는 1개: "무료 진단 예약하기". 브랜드 CTA 색은 카카오 옐로. 같은 목적 버튼은 같은 문구·같은 색.
- 모바일 고정 바(.sticky-cta)도 버튼 1개. 히어로 CTA(#heroCta)가 화면에 보이면 고정 바는 `hidden` 속성으로 숨긴다(class 토글 금지). 판정은 IntersectionObserver + load·resize·pageshow 시 getBoundingClientRect.
- 전화·카톡·자가진단 등 나머지 경로는 하단 섹션으로.
- 폼은 예약 경험: 성함+연락처+개인정보 동의(privacy 링크)가 최소 구성, 통화 희망 시간대(오전/오후/아무 때나), 업종·문의내용은 선택. 동의 체크박스 미리 체크 금지. 허니팟(website) 필드. 전송 실패 시 전화·카톡 탈출구 버튼. 성공 메시지 "예약됐습니다. 평일 09:00~18:00 중 정하신 시간대에 전화드리겠습니다. 급한 문의는 1666-2425로 연락해 주세요.".
- 첫 화면 카피는 선언형(당사자 어조), 혜택이 먼저. 경고·훈계는 다음 섹션.
- 신뢰 문구는 폼 안(전환 지점) 한 곳에만. 같은 문구를 반복하면 광고처럼 읽힌다.
- 신뢰는 검증 가능한 사실로: 대표 얼굴·이력·사업자번호·주소 노출, 실적은 체감형, 강점은 이유와 함께("모든 신청을 받지는 않습니다 — 착수금 없이 성과로만 보수를 받는 구조라 안 될 일을 맡을 수 없기 때문").

### 4-1. 홈 구조 (hero-diet 기준)

세로 순서는 "얼마를 몇 %에 → 나도 되나 → 사기 아냐"다.

1. 히어로(확정 문구): 라벨 "비즈니스 메이커 · 전국 무료 상담" · H1 2줄 카테고리 "소상공인·중소기업 / 정책자금 컨설팅" · 서브 숫자 "사장님 {N}분이 정책자금 {억}억을 받았습니다 ({기간})"(home-sub 마커, build_cases 치환, 카운트업·HTML엔 최종 숫자 고정) · CTA "무료 진단 예약하기" 1개(옐로) · 안내 "진단은 무료, 정책자금은 착수금이 없습니다" · 상담 사진(assets/hero-consult.webp, 교체 금지)
2. 신뢰 칩 4개 스트립: 받은 사례 · 영업 12년 · 착수금·진행비용 없음 · 전국 무료 상담
3. 최근 사례 독립 섹션. 제목 아래 조건 밴드: "실행 사례 기준 금액 min~max · 금리 연 min~max (기간, N건)" — build_cases band()가 생성
4. 왜 비즈니스 메이커 한 줄 + 흔한 방식 비교
5. 회사소개 3줄
6. 업종 타일 6개(/industry/<slug> 랜딩이 있는 업종만 직결, 나머지는 /cases)
7. FAQ 홈 5개(전체는 /faq)
8. 폼(회사소개 섹션 앞) — h1 1개, conversion.js 1회

내비 순서: ① 소상공인 정책자금 컨설팅(/sosangin) ② 중소기업 정책자금 컨설팅(/jungsogieop) ③ 받은 사례(/cases) ④ 자금 안내(기관별 드롭다운) ⑤ 기업인증 ⑥ 회사소개 ⑦ [무료 진단 예약] 버튼. 창업컨설팅·기업광고·교육은 푸터 "다른 업무" 블록에 둔다 — URL·페이지·내부링크는 유지하고 삭제·리다이렉트하지 않는다.

홈 구조는 tests/가 고정한다. 구조를 바꾸면 테스트와 이 문서를 같은 커밋에서 갱신한다. home-proof·home-h1·home-recent·why-big 마커와 히어로 숫자는 build_cases가 관리 — 손으로 쓰지 않는다.

## 5. 디자인 — v4 "장부와 공문서"

- 제목 명조(Noto Serif KR, CSS 변수 `--display`), 표 숫자체, 카드 대신 괘선 목록, 낮은 라운드, 종이 톤 배경.
- 히어로 빛번짐·격자·그라데이션 없음.
- 형광펜 밑줄(background 그라데이션) 강조 금지. 큰 제목 핵심 단어는 글자색(브랜드 옐로), 작은 문구는 굵기로만.
- 자동으로 넘어가는 슬라이드형 히어로 금지. 움직임은 장식만: H1 숫자 카운트업(HTML엔 최종 숫자 고정), CSS 배경 점 패턴. prefers-reduced-motion이면 즉시 표시.
- 스크롤 리빌은 conversion.js가 `<style data-rv>` 주입, `.rv` 네임스페이스. 표는 20행 이하만 행 단위.
- 승인사례 마퀴: 무한 스크롤, hover 시 정지, 양끝 페이드, reduced-motion 시 수동 스크롤.
- 서브페이지 전체가 같은 테마. 새 페이지도 v4를 따른다.

## 6. 모바일

- viewport 메타태그. 제목은 clamp()로 유동. 한글은 `word-break: keep-all`.
- ≤680px: 본문 16px, 행간 1.75~1.8. 버튼은 풀폭. 섹션 여백 축소.
- PC 전용 줄바꿈은 `<br class="pc">` + 미디어쿼리 display:none. 태그 앞에 반드시 공백(없으면 모바일에서 단어가 붙는다).
- 로고를 flex 컨테이너에 넣을 때 텍스트는 span으로 감싼다(gap이 글자 사이에 낀다).

## 7. 광고 랜딩

- 유료광고 랜딩에는 폼이 반드시 있다. 분기용 메뉴판 페이지에 광고 착지 금지.
- 키워드별로 해당 주제 페이지에 직결. 검수 제약으로 직결 불가하면 허브 페이지에 분야 선택형 간편 폼.
- 첫 화면에 유입 검색어가 보이도록 키워드 에코 뱃지.
- 광고 심사받은 URL에서 다른 도메인으로 자동 리다이렉트 금지(광고 중단 사유). 페이지 내 코브랜딩·사용자 클릭 링크·전환 후 감사 페이지로 안내.
- 검색어 보고서로 실제 유입 검색어 확인 후 안 맞는 검색어(무상지원 계열 등)는 제외 키워드 등록.

## 8. 롱테일 키워드·의도 랜딩

- 후보는 검색량이 아니라 검색의도로 고른다. 우선순위: 상황형 > 지역+카테고리 > 비용·사기 > 자금명 세부 > 업종·인증.
- 착지: 상황형 → /situation/<slug>, 지역형 → 지역 랜딩, 업종 → /industry/<slug>, 비용·사기 → 블로그 시리즈, 자금명 세부 → 기존 상세 페이지 FAQ 추가.
- 검색량 검증은 네이버 검색광고 키워드도구(월간 검색수 PC+모바일, 경쟁정도). 10건 미만 제외, 100~1,000건대 저경쟁이 핵심 구간.
- 의도 랜딩도 2·3·4절 전부 적용(전용 title·폼·FAQ·JSON-LD).

## 9. 빌드·코드 규칙

- 데이터 원본은 구글시트 3탭(원장·자금·재단). ledger 워크플로가 매시 동기화한다. 로컬 CSV·xlsx는 폴백이며 손으로 고치지 않는다.
- 빌더 체인 순서: cases → funds → jaedan → gaein → consulting → jungjin → editorial → education → build_lastmod. 마지막이 항상 build_lastmod. HTML을 손으로 고치고 스탬퍼를 안 돌리면 pytest가 실패한다.
- 날짜는 `tools/builddate.build_date()`만 쓴다. 빌더에서 date.today()·datetime.now()를 직접 호출하지 않는다.
- CSS: 페이지마다 스타일 블록이 2~3개다. 첫 블록에 넣는 전역 규칙은 반드시 부모 선택자(.wrap/main/body)로 명시도를 올린다. 전파 순서: sojingong 첫 블록 + tools/cases_tpl.html → 8빌더 실행 → 남은 정적 페이지 일괄 치환.
- 저장소 루트가 Worker 정적 에셋으로 통째로 서빙된다. 비공개 파일(문서·테스트·설정·지침)은 반드시 .assetsignore에 넣는다. 호스팅 설정은 wrangler.jsonc(not_found_handling=404-page)가 기준.
- IndexNow 핑은 루트 한정.
- 복합 기관 표기("기술보증기금 + 소상공인…")는 먼저 등장한 기관으로 분류.
- index.html은 zip 통째 덮어쓰기 대신 줄 단위로 고친다. 적용 전 `git log -3 -- index.html`로 외부 편집을 확인한다.
- 작업 중 되돌릴 땐 `git checkout -- .` 금지. 파일 경로를 명시하거나 git stash.

## 10. 테스트·검증

- 전환 관련 동작(고정 바 숨김·폼 제출·CTA 스크롤)은 JS 소스 문자열 검사가 아니라 브라우저 동작 검사(Playwright Chromium 390×844)로 둔다. 문자열 검사는 통과하는데 실동작이 틀린 사례가 있었다.
- 게이트: 로컬 `python -m pytest`(푸시 전) → pr-check 워크플로(main 푸시·PR마다 pytest+브라우저 테스트+빌더 체인 churn 검사).
- 작업 절차: `git pull --ff-only` → 적용 → pytest → 빌더 체인 2회(churn 0) → 커밋·푸시 → 라이브 검증(curl --retry + 크기, 대상 전부 도달 폴링, grep -o | wc -l) → 스크린샷·수치 보고.
- 모션·렌더 검증은 Playwright 폰 에뮬레이션으로. 크롬 확장 숨김 탭은 rAF·IntersectionObserver가 동결돼 오판한다. 데스크톱 창을 390으로 줄이면 스크롤바 때문에 실제 폰과 다르다.
- 납품 전 확인: 눈에 안 보이는 특수문자 0, "갚다" 계열 0, 보장성 표현 0, JSON-LD 파싱, placeholder 잔존 0.
- 폼은 허니팟 테스트가 아니라 실제 제출로 메일 도착까지 확인(엔드포인트가 발송 실패에도 ok:true를 돌려주므로 응답코드로 판정 불가).
- 배포 후 모바일 실기기에서 첫 화면·버튼·줄바꿈 확인. 카톡 공유 미리보기 캐시는 developers.kakao.com/tool/debugger/sharing 에서 초기화.
- Cloudflare requests 숫자는 방문자 수가 아니다(봇·에셋 포함). 실방문은 Web Analytics·GA4(G-DBGR3P6ZHD, 주요 이벤트 generate_lead·kakao_click)로 본다.
