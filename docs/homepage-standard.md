# 비즈니스 메이커 홈페이지 제작 규격 (bmaker.kr)

기준일: 2026-10-01 · 적용 범위: bmaker.kr 전 페이지, 광고 랜딩, 빌더·템플릿·CSS·JS
읽는 사람: Claude Code, Codex, 그 외 이 저장소를 편집하는 모든 에이전트

이 문서는 사이트 작업의 단일 기준이다. 페이지·카피·CSS·빌더를 만지기 전에 읽는다.
작업이 규격과 충돌하면 코드가 아니라 이 문서를 먼저 고치고(변경 이력 남김), 그 다음 코드를 고친다.
규격에 없는 판단은 대표에게 묻는다. 추측으로 채우지 않는다.

## 0. 원칙

- 문의 = 유입 × 전환율. 홈페이지는 "문의를 받을 준비가 된 그릇"이다. 유입은 별도로 부어야 한다.
- 브랜드 톤: 빈말하지 않는다. 다 되는 것처럼 말하지 않는다.
  마무리 문장: "다 되는 것처럼 말씀드리지 않습니다. 대신, 될 수 있는 방법을 함께 찾겠습니다."
- 회사명 표기는 "비즈니스 메이커"(띄어쓰기) 하나로 통일한다. 로고 이미지 외에 "비즈니스메이커", "BUSINESS MAKER"를 본문·title·JSON-LD에 쓰지 않는다.
- "진단"은 서비스명, "정책자금 컨설팅"은 카테고리다. 둘 다 있어야 한다. 컨설팅이라는 단어를 진단으로 바꿔 없애지 않는다(AI·검색이 업종을 잃는다).
- 섹션당 메시지 하나. 한 섹션에 두 가지 말을 넣지 않는다.
- 사장님이 바로 알아듣는 말로 쓴다. 업계·통계 용어, 자체 조어, AI스러운 말투 금지.

- 면책 조항과 작성자 서명은 모든 안내 페이지에 둔다.
- **공식 제도 조건과 회사 사례 통계를 구분한다.** 공식 조건 숫자(대상·한도·금리·접수)에는 공고 링크·기준일·적용
  범위를 붙이고, 회사가 제공하는 확정 조건처럼 쓰지 않는다. 실적 숫자는 원장/빌더 생성값만 쓴다.
- bmaker.kr과 codedaum 두 사이트의 실적 숫자는 항상 같아야 한다.
- 원장 익명화 범위는 사례 주석에 그대로 명시: 지역·업종·매출 구간은 범주화·일부 조정, 기관·자금·금액·금리·실행 시점은 실제.

## 2. SEO

- 검색 목적 하나를 충분히 해결하는 대표 페이지를 둔다. 같은 뜻의 검색어·띄어쓰기 변형은 한 페이지에서 다루며, 서로 다른 목적만 분리한다. 검색어·지역 이름만 바꾼 복제 페이지를 늘리지 않는다.
  같은 의도로 두 페이지가 경쟁하면 하나로 합치고 301 한다. 재단 지역 페이지는 /jaedan 본체를 대표로 두고 위로
  링크한다. 근거: `혁신성장촉진자금` 구글에서 자사 URL 2개가 2위·6위로 동시 노출(2026-09-20 실측).
- 페이지마다: 고유 title(핵심검색어 | 보조검색어 | 비즈니스 메이커, 50자 내외), description 150자 내외, canonical, h1 1개.
  **길이는 편집 가이드이지 순위 공식이 아니다.** 핵심 의도·가독성·정확성을 먼저 보고 키워드를 나열하지 않는다.
- **og:title 은 title 과 같은 값으로 둔다. 빌더가 생성하며 손으로 따로 쓰지 않는다.**
  2026-09-20 실측에서 구글이 `<title>` 이 아니라 `og:title` 을 검색결과 제목으로 표시했다 — 둘이 다르면
  title 만 고쳐도 검색결과가 안 바뀐다. 어긋난 49장 정리는 B묶음(10/6 이후).
- 정본 URL은 확장자 없는 형태(/sojingong). canonical·sitemap·llms.txt·내부링크 전부 이 형태. 새 페이지도 동일.
- 기관·제도명은 정식명칭(약어) 병기: 소상공인시장진흥공단(소진공).
- 각 페이지에 "본 안내는 YYYY년 M월 기준". 푸터 "최종 업데이트"와 JSON-LD dateModified, sitemap lastmod는 build_lastmod가 자동 삽입 — 손으로 쓰지 않는다.
- 날짜는 **실질적인 내용 변경과 확인 근거**를 반영한다. 단순 빌드로 전 페이지를 최신 정보처럼 표시하지 않는다.
  build_lastmod 의 해시 범위(`<main>`·title·description)와 `data_date()` 가 그 장치다. 봇이 얕은 체크아웃으로
  돌면 이 보장이 깨진다(2026-09-20 `6a099e9`).
- 홈 head의 Google Search Console 소유권 메타태그는 영구 유지. 삭제 금지.
- www → 루트 301(Cloudflare 리다이렉트 규칙, Preserve query string 켬). Netlify식 `/* / 301` 캐치올은 무한 리다이렉트 — 사용 금지.
- 검색 등록 3곳(네이버 서치어드바이저·Google Search Console·Bing Webmaster)은 도메인 기준이라 유지된다. MX 등 메일 레코드는 절대 건드리지 않는다.
- 홈 title은 소상공인·중소기업 정책자금 컨설팅이라는 대상·분류를 설명한다. 소재지는 회사 정보에 정확히 표시하며 전국 대상 홈 제목을 특정 지역으로 한정하지 않는다.

## 3. GEO

- robots.txt: GPTBot·OAI-SearchBot·ClaudeBot·PerplexityBot·Google-Extended·Yeti 명시 허용. Cloudflare의 AI 학습 차단 옵션은 끈다.
- llms.txt·llms-full.txt 필수. 회사 요약, 주요 페이지, 회사의 관점(착수금 0원·거절은 진단서·선별 진행), 핵심 사실(면책 포함). 사이트 수치·전화번호와 항상 일치. 응답 헤더 `text/plain; charset=utf-8`(_headers).
- FAQ: 질문은 실제 고객 질문 문장으로 쓰되 **맥락이 명확하도록 다듬는다** — 오타·특수기호·조각 문장을 제목에
  복제하지 않는다(GSC 실검색어에 `26년도는?` 같은 조각 다수). 답변 첫 문장은 완결된 직답.
  화면 FAQ와 FAQPage JSON-LD는 100% 일치 — FAQ를 고치면 스키마도 같이 고친다.
- 구조화 데이터 세트: FAQPage·Service·BreadcrumbList·WebSite·ProfessionalService(LocalBusiness, telephone·sameAs 포함). 비벗(NHN KCP)은 sameAs가 아니라 memberOf.
- sameAs에는 실제 등록된 프로필만(인스타·구글 비즈니스 프로필·네이버 스마트플레이스·당근·카카오맵). 등록 안 된 채널을 미리 넣지 않는다.
- 상세 페이지 간 "함께 보면 좋은 안내" 상호 링크로 주제 클러스터.
- 회사명·대표·전화·주소는 전 채널 동일 표기(상호 "비즈니스 메이커", 마곡 공항대로 213, 1666-2425).
- **회사 정의는 한 문장으로 통일한다:** "비즈니스 메이커는 소상공인·개인사업자와 제조·기술 중소기업 법인의 정책자금을
  상담하는 정책자금 경영컨설팅 회사입니다." 홈 히어로 설명·회사소개·llms 파일 첫 문장·Organization description 이 대상.
  짧게 쓸 때는 "정책자금 경영컨설팅 회사". 회사를 가리켜 "민간 경영컨설팅"·"민간 컨설팅 회사"·"민간 진단 회사"를 쓰지 않는다
  (업계 일반을 설명하는 "민간 컨설팅" 문장은 해당 없음). 검사: `tests/test_company_definition.py`.
- **검토자 표기:** 자금·재단·서비스·정보성 글·블로그·도시 페이지 본문 끝에 "작성 비즈니스 메이커 · 검토 김상표(대표) ·
  최종 확인 {날짜}" 한 줄. 날짜는 데이터 확인일(자금·재단·도시) 또는 대표 검토일(YYYY-MM-DD, 새 바이라인은 월 단위 금지)이며 빌드일을 쓰지 않는다. 같은 날짜로
  JSON-LD WebPage 노드에 reviewedBy(Person `#founder`)·lastReviewed 를 단다(`tools/reviewer.py`, `build_lastmod` 가 스탬프,
  블로그는 `build_blog`). Person 상세(직함·경력)는 홈 `#founder` 한 곳에만. 확인되지 않은 자격·학력은 넣지 않는다.
- **대표 자격**(대표 확인 2026-10-04): ISO 9001·14001·45001 내부심사원 · 창업상권분석지도사 1급(민간자격) · AI 창업지도사(민간자격).
  홈 회사소개의 "대표 자격" 항목(김상표 대표 개인 자격)과 Person `hasCredential` 에만 쓴다. 회사가 ISO 인증을 받은 것처럼
  읽히는 문구("ISO 인증 기업" 등) 금지, 자격 항목 안에 "인증"이라는 말을 쓰지 않는다. 검사: `tests/test_ceo_credentials.py`.
- **들어오는 링크:** sitemap 의 모든 페이지는 다른 페이지 본문·메뉴·푸터에서 들어오는 링크가 1개 이상(`tests/test_inbound_links.py`).
  공통 푸터에 `/region`(지역별 창구)·`/faq` 링크를 둔다.

## 4. 전환

- 히어로 주요 CTA는 1개: "무료 진단 신청". 폼 신청은 브랜드 블루, 카카오 옐로는 실제 카카오 이동에만 사용. 정책자금 전용 CTA는 문의 분야도 정책자금으로 선택한다. 일반 상담 링크는 기존 선택을 보존한다.
- 고정 바(.sticky-cta)는 전 페이지. **신청 버튼 1개(크게, 브랜드 블루 #234780) + 카톡·전화 작은 보조 아이콘** — 시선은 신청 하나로. 휴대폰(≤840px)은 화면 아래 한 줄, PC 는 우측 하단 상자. 히어로 CTA(#heroCta)·그 페이지 폼이 화면에 보이거나, 신청 창이 열렸거나, 키보드가 올라와 있으면(입력 초점 또는 visualViewport 축소) `hidden` 속성으로 숨긴다(class 토글 금지). 판정은 IntersectionObserver + load·resize·pageshow 시 getBoundingClientRect. 본문·FAQ·푸터를 가리지 않게 아래 여백과 scroll-padding-bottom 을 바 높이만큼 둔다.
- 신청 버튼은 다른 페이지로 보내지 않는다 — 그 자리 신청 창(휴대폰 아래 시트·PC 가운데 창)에 그 페이지 폼이 열린다(홈은 기존 스크롤). 폼 없는 페이지는 페이지 끝에 인라인 폼과 같은 간편 신청 폼을 conversion.js 가 붙이고(정본 tools/inline_form.py, build_lastmod 가 동기화), 휴대폰 5화면을 넘는 긴 페이지는 본문 중간에 신청 버튼을 한 번 둔다. 신청 버튼 색은 전 사이트 #234780 하나. 검사 `tests/test_apply_everywhere.py`.
- 전화·카톡·자가진단 등 나머지 경로는 폼·연락처 섹션으로. 모바일 첫 화면의 헤더 상담 버튼은 중복 노출하지 않는다.
- 폼은 예약 경험: 성함+연락처+개인정보 동의(privacy 링크)가 최소 구성, 통화 희망 시간대(오전/오후/아무 때나), 업종·문의내용은 선택. 동의 체크박스 미리 체크 금지. 허니팟(website) 필드. 전송 실패 시 전화·카톡 탈출구 버튼. 성공 메시지 "예약됐습니다. 평일 09:00~18:00 중 정하신 시간대에 전화드리겠습니다. 급한 문의는 1666-2425로 연락해 주세요.".
- 신청은 유입 경로(`landing_url`)를 함께 보낸다 — 광고 파라미터(utm·n_media 등 네이버 검색광고·gclid·fbclid)만 남긴 착지 주소. CRM 이 이것으로 출처(6.홈페이지/7.메타)와 근거(파워링크/자연 유입)를 가린다. Referrer-Policy 때문에 Referer 헤더에는 경로·쿼리가 없어 본문으로 보낸다. 탭 단위(sessionStorage)로 기억해 광고 착지 → 다른 페이지 → 신청도 광고로 남는다. 검사 `tests/test_conversion.mjs`.
- 첫 화면 카피는 선언형(당사자 어조), 혜택이 먼저. 경고·훈계는 다음 섹션.
- 비용 구조는 FAQ 비용 질문의 답(화면·FAQPage JSON-LD 같은 문장)과 llms 파일에서만 설명한다. 진단 섹션·안내 박스·폼·메타 등 그 외 위치는 "진단은 무료입니다."까지만 쓴다(1절 표). 검사는 `tests/test_fee_copy.py`.
- 신뢰는 검증 가능한 사실로: 대표 얼굴·이력·사업자번호·주소 노출, 실적은 체감형, 강점은 이유와 함께(비용 구조를 이유로 드는 문장은 FAQ 비용 답에서만 — 1절 표).
- 전문가 운영은 사용자 확인에 따라 "각 분야 전문가와 상시 협업"으로 표현한다. 상주·사내 고용·24시간 응답으로 확대 해석하지 않으며, 업무별 담당·범위·비용은 사전에 안내한다.

### 4-1. 홈 구조 (2026-09-21 CRO 개정)

상단 주요 구역은 "내 사업을 검토하나 → 무엇을 확인하나 → 비슷한 사례가 있나"다. 경쟁사 사용 빈도를 전환 효과로 단정하지 않는다.

1. 히어로: 정책자금 컨설팅 라벨 · 가능성 진단 중심 H1 · 진단 내용 설명(첫 문장은 3절 회사 정의 문장) · 블루 CTA 1개 · 기존 상담 사진. 버튼 아래 비용·면책·실적 설명과 사진 아래 사례 카드는 두지 않는다. 심사 주체 안내는 다음 진단 섹션(비용 구조는 FAQ에만), 원장 집계는 사례 섹션으로 이동한다. 건수를 고객 수(분)로 바꾸지 않는다.
2. 진단에서 확인할 3가지: 사업 현황, 자금 용도, 기관별 조건·준비사항. 진행 여부는 검토 뒤 안내하고 승인은 기관 심사라는 한계를 분명히 한다.
3. 원장 기반 사례 3개: 개인·법인 사례를 모두 포함한다(해당 형태의 공개 원장이 있는 경우). 개인사업자·중소기업 법인 안내 경로와 원장 기반 형태별 집계를 함께 표시한다. 지역·업종·업력·기관·시점·금액을 각 사례 ID의 링크와 연결. 고객 실명 및 신용점수 유인 문구는 제외한다.
4. 기관 안내와 증빙. 공공기관이나 공식 위탁기관처럼 보이지 않도록 고지 문장 "비즈니스 메이커는 정부·공공기관이 아닌
   정책자금 경영컨설팅 회사입니다."를 둔다(홈·회사소개 1회 이상, 삭제 금지).
   홈 증빙은 기관 안내문·약정 캡처 4장 이상, 장수 축소는 대표 승인 필요. 계산서·송금 대화 캡처는 홈에 싣지 않는다(`/cases` 공개는 유지). 검사: `tests/test_cases_ledger.py`.
5. 기존 정책자금·마케팅·창업·인증·교육 서비스 및 진행 절차 유지.
6. 폼은 회사소개 앞, h1 1개 및 conversion.js 1회 유지. 신청 시 서류 첨부를 요구하지 않는다.
7. 회사소개·전문가·FAQ·가이드·가이드북 이벤트·뉴스 유지. 직접 신청 가능 여부와 업무 비용을 FAQ에서 명확히 답한다.

홈 구조 변경은 테스트와 이 문서를 함께 갱신한다. 사례 섹션의 home-proof·home-matched-cases 마커의 숫자·사례는 build_cases가 관리한다. 사진 아래 home-recent 표시는 폐기한다. H1은 편집 카피로 유지하며 빌더가 덮어쓰지 않는다. home-h1·why-big 마커는 폐기한다.

## 5. 디자인 — v4 "장부와 공문서"

- 제목 명조(Noto Serif KR, CSS 변수 `--display`), 표 숫자체, 카드 대신 괘선 목록, 낮은 라운드, 종이 톤 배경.
- 히어로는 어두운 유리 건축 브랜드 이미지와 가독성용 네이비 오버레이를 허용한다. 실제 자사 사무실이나 보유 건물로 표현하지 않는다. 배경은 경량 웹 이미지로 제공하고 얼굴 사진은 별도 원본 자산을 유지한다.
- 형광펜 밑줄(background 그라데이션) 강조 금지. 큰 제목 핵심 단어는 글자색(브랜드 옐로), 작은 문구는 굵기로만.
- 자동 슬라이드·배경 동영상·무한 반복 히어로 모션은 사용하지 않는다. 첫 진입의 제목·사진 이동과 5초 이내 장식 빛 이동을 허용하며 모든 문구는 처음부터 HTML에 존재하고 읽을 수 있어야 한다. prefers-reduced-motion에서는 모션 없이 즉시 표시한다. 모바일은 이동 폭과 배경 크기를 줄인다.
- 스크롤 리빌은 conversion.js가 `<style data-rv>` 주입, `.rv` 네임스페이스. 표는 20행 이하만 행 단위.
- 승인사례 마퀴: 무한 스크롤, hover 시 정지, 양끝 페이드, reduced-motion 시 수동 스크롤.
- 서브페이지 전체가 같은 테마. 새 페이지도 v4를 따른다.

## 6. 모바일

- viewport 메타태그. 제목은 clamp()로 유동. 한글은 `word-break: keep-all`.
- ≤680px: 본문 16px, 행간 1.75~1.8. 버튼은 풀폭. 섹션 여백 축소.
- PC 전용 줄바꿈은 `<br class="pc">` + 미디어쿼리 display:none. 태그 앞에 반드시 공백(없으면 모바일에서 단어가 붙는다).
- 로고를 flex 컨테이너에 넣을 때 텍스트는 span으로 감싼다(gap이 글자 사이에 낀다).
- 대표 상담 사진은 모바일·PC 모두 원본 비율을 유지한다. 고정 높이와 cover로 얼굴·상반신을 잘라내지 않는다.
- 작은 사이트 아이콘은 기존 로고 형태를 보존하고 사방 안전 여백을 둔다. 헤더 로고와 별도 관리한다.

## 7. 광고 랜딩

- 유료광고 랜딩에는 폼이 반드시 있다. 분기용 메뉴판 페이지에 광고 착지 금지.
- 키워드별로 해당 주제 페이지에 직결. 검수 제약으로 직결 불가하면 허브 페이지에 분야 선택형 간편 폼.
- 첫 화면에 유입 검색어가 보이도록 키워드 에코 뱃지.
- 광고 심사받은 URL에서 다른 도메인으로 자동 리다이렉트 금지(광고 중단 사유). 페이지 내 코브랜딩·사용자 클릭 링크·전환 후 감사 페이지로 안내.
- 검색어 보고서로 실제 유입 검색어 확인 후 안 맞는 검색어(무상지원 계열 등)는 제외 키워드 등록.

## 8. 롱테일 키워드·의도 랜딩

- 후보는 검색량이 아니라 검색의도로 고른다. 우선순위: 상황형 > 지역+카테고리 > 비용·사기 > 자금명 세부 > 업종·인증.
- 착지: 상황형 → /situation/<slug>, 지역형 → 지역 랜딩, 업종 → /industry/<slug>, 비용·사기 → 블로그 시리즈, 자금명 세부 → 기존 상세 페이지 FAQ 추가.
- 검색량 검증은 네이버 검색광고 키워드도구(월간 검색수 PC+모바일). **광고 경쟁정도는 SEO 난이도가 아니다.**
  10건 미만 제외는 유지한다(GEO 목적 페이지만 예외). **100~1,000건대가 핵심이라는 절대 기준은 폐기한다** —
  검색량은 참고값이고, 상위 결과 유형(기관·은행·블로그)·자사 실적·내용 차별성으로 판단한다.
  근거: `소상공인정책자금` 월 172,100 인데 상위 8이 전부 기관·정부·은행, `보증서대출` 월 260 인데 평균순위 7.0.
- 의도 랜딩도 2·3·4절 전부 적용(전용 title·폼·FAQ·JSON-LD).
- 교육·출강은 소상공인·개인사업자뿐 아니라 중소기업·법인 대표와 재무·회계·총무 담당자를 포함한다. 60·90·120분 기본 과정과 맞춤 출강을 제공하며 시간·지역·비용·담당은 사전 협의한다. 교육 실적을 컨설팅 실적과 혼동하지 않는다.
- 교육 과정·시간표·결과물은 docs/education-programs.json에서 화면과 인쇄본을 함께 생성한다. 추가 실무 콘텐츠는 docs/funding-guides.json, 관련 링크는 docs/topic-links.json을 사용하고 기존 editorial 빌더에 통합한다.
- 실적 표는 현재 원장 기준으로 생성한다. 과거 고정 집계는 기준일·대상 표본을 명시하고 현재 전체 집계처럼 사용하지 않는다. 숫자만 최신으로 바꾸고 근거 사례를 과거에 남겨두지 않는다.

### 8-1. 도시 페이지(/region/<city>) 생성 규칙

도시 이름만 바꾼 도어웨이 페이지를 막기 위한 생성 조건이다. 하나라도 어기면 그 도시 페이지는 만들지 않는다.
검사는 `tests/test_region.py`, 빌더(`tools/build_region.py`)는 같은 조건으로 생성 전에 멈춘다.

1. **그 도시 고유 사실 3개 이상, 전부 공식 출처.** 사실 = 재단 관할 지점 · 소진공 관할 센터 · 시·군·구 자체 자금 공고
   (육성자금·특례보증·이자지원). 출처는 정부(`*.go.kr`·서울 자치구 `*.seoul.kr`)·지역 신용보증재단·소진공 공식
   도메인만. **시·군 자금은 공고 단위로 센다(한 공고의 세부 항목을 따로 세지 않음). 공식 출처 사실 3개 이상, 그중
   시·군 자금 1건 이상 필수** — 재단 지점·소진공 센터 안내만으로는 통과하지 못한다.
   - **재단 지점 관할 근거는 재단 공식 사이트 또는 해당 지자체 공식 공고(`*.go.kr` 등)의 명시 문장. 추정 금지**
     (주소·지점명으로 관할을 짐작하지 않는다). 둘이 다르면 임의로 고르지 않고 대표에게 보고한다.
   - **도 전체 사업(경기도·충남도 공통 등)은 도시 고유 사실로 세지 않는다** — 페이지에 "참고"로 표시는 가능
     (`data-fact="province-fund"`, 개수에서 제외).
2. **사실 조합 중복 금지.** 두 도시 페이지의 사실 집합이 같으면 실패(같은 지점·같은 센터만 공유하는 인접 도시 방지).
3. **본문 유사도.** 두 도시 페이지의 본문에서 도시명을 지운 뒤 5어절 조각 자카드 유사도가 0.6을 넘으면 실패.
4. **재단↔도시 양방향 링크.** 도시 페이지는 해당 광역 `/jaedan-<시도>` 로, 그 재단 페이지는 소속 도시 페이지 전부로 링크.
   재단 설명·사례·FAQ는 재단 페이지에만 두고 도시 페이지는 링크한다(2절 대표 페이지 원칙).
5. **확인일 90일 초과 실패.** 사실마다 확인일을 두고, 빌드일 기준 90일이 지난 사실이 있으면 실패 — 재확인 후 갱신한다.

페이지 계약(테스트가 읽는 형태): `<main data-city="<도시명>" data-jaedan="jaedan-<시도>">`, 사실 요소마다
`data-fact="<종류>" data-fact-id="<기관/대상 식별자>" data-source="<출처 URL>" data-checked="YYYY-MM-DD"`.
세는 종류는 `jaedan-branch`·`semas-center`(연락처)·`city-fund`(시·군 자금, `data-source` 공고 URL 기준으로 1건).
`jaedan-branch` 의 `data-source` 는 재단 또는 지자체 공식 도메인이어야 한다. 받은 사례는 원장이 시도 단위라(1절 익명화 범위) 도시 사실로 세지 않고
"{시도} 사례"로만 표시한다. 조사 원자료: `docs/region/`(비공개).

**목록 허브 `/region`** (2026-10-04): 도시 페이지를 시도별로 묶은 목록. 도시 페이지의 사실(재단 지점 축약·센터·공고 수)만
다시 보여주고 새 사실을 쓰지 않는다. `build_region` 이 도시 페이지와 함께 만든다(도시 페이지가 아니라 신규 도시 정지 대상 아님).
도시 페이지 → 자금 페이지 링크는 **소상공인 대상 공고(이름에 소상공인·미소금융·청년창업)와 성격이 비슷한 소진공 자금만**,
최대 3개(`FUND_PAGES`). 중소기업 대상 공고만 있는 도시는 잇지 않는다.

## 9. 빌드·코드 규칙

- 데이터 원본은 구글시트 3탭(원장·자금·재단). ledger 워크플로가 매시 동기화한다. 로컬 CSV·xlsx는 폴백이며 손으로 고치지 않는다.
- 빌더 체인 순서: cases → funds → jaedan → region → gaein → consulting → jungjin → editorial → education → hubs → blog → build_lastmod. 마지막이 항상 build_lastmod. (pr-check·ledger 두 워크플로가 같은 순서)
- 블로그(`/blog`, `tools/build_blog.py`): 원본은 `posts/YYYY-MM-DD-slug.md`(비공개). 날짜는 frontmatter(date·updated)만 쓰고 빌드일을 쓰지 않는다. 첫 문단 직답·작성자 줄·면책·기준일·FAQ↔FAQPage 일치는 빌더가 만든다. **블로그 제목은 자금 정식명으로 시작하지 않는다** — 자금 검색어는 자금 페이지 몫이고, 블로그는 상황·절차·사례 관점으로 쓴다(2026-10-04 WordPress 카니발 진단). 금칙어·비용 구조 문구가 있으면 빌더가 멈춘다. 검사 `tests/test_blog.py`. HTML을 손으로 고치고 스탬퍼를 안 돌리면 pytest가 실패한다.
- 날짜는 `tools/builddate.build_date()`만 쓴다. 빌더에서 date.today()·datetime.now()를 직접 호출하지 않는다.
- CSS: 페이지마다 스타일 블록이 2~3개다. 첫 블록에 넣는 전역 규칙은 반드시 부모 선택자(.wrap/main/body)로 명시도를 올린다. 전파 순서: sojingong 첫 블록 + tools/cases_tpl.html → 8빌더 실행 → 남은 정적 페이지 일괄 치환.
- 저장소 루트가 Worker 정적 에셋으로 통째로 서빙된다. 비공개 파일(문서·테스트·설정·지침)은 반드시 .assetsignore에 넣는다. 호스팅 설정은 wrangler.jsonc(not_found_handling=404-page)가 기준.
- IndexNow 핑 대상은 sitemap.xml 에 실린 URL 과의 교차로 정한다(하위 디렉터리 `/industry/…`·`/region/…` 포함).
  푸시 핑은 바뀐 HTML 중 sitemap 에 있는 것만, 수동 실행(workflow_dispatch)은 sitemap 전체. 새 페이지는 sitemap 등록이 곧 핑 대상 등록이다.
- 복합 기관 표기("기술보증기금 + 소상공인…")는 먼저 등장한 기관으로 분류.
- index.html은 zip 통째 덮어쓰기 대신 줄 단위로 고친다. 적용 전 `git log -3 -- index.html`로 외부 편집을 확인한다.
- 작업 중 되돌릴 땐 `git checkout -- .` 금지 (.claude/settings.json deny 로 차단됨 — 파일 경로를 명시한 checkout/restore 만 허용). 파일 경로를 명시하거나 git stash.

### 9-1. 접수 배지 (/schedule · 자금 상세)

- 서버는 항상 "공고상 YYYY-MM-DD 예정" 형태로 렌더하고, 시작일이 지난 뒤 쓸 문장을 `data-sched-start`·
  `data-sched-passed`·`data-sched-passed-class` 에 실어 보낸다. 상태 전환은 conversion.js 가 **방문 시점
  날짜**로 한다 — 재빌드 없이 상태가 맞고, 빌드 날짜가 HTML 에 들어가지 않아 산출물이 매일 흔들리지 않는다.
- 배지 문구에 "현재 접수 중" 같은 시점 의존 표현을 서버 렌더로 굳히지 않는다. 접수 표시는 확인 시점의 공식
  안내이며 잔여 예산을 뜻하지 않는다는 문장을 함께 둔다.
- 검사는 `tests/test_schedule_badges.py`(브라우저 동작, 시작 전 / 시작일 경과 두 상태).
